Engineering Contrast

What a read-modify-write limiter gets wrong.
(And what one atomic step does instead.)

Most hand-rolled limiters fetch quota from a database, compute a decision in application memory, and write the result back. Under concurrency, this allows double-spend bursts.

Read, Compute, Write (Unsafe)

  • 01. Read and write are separate operations with a race window.
  • 02. System clock timestamps drift across nodes.
  • 03. Window edges permit up to 2x configured burst limit.
  • 04. Network timeouts leave quota in corrupt undefined states.

One Atomic Step (REQNX)

  • 01. Transition evaluates entirely inside atomic store boundary.
  • 02. Monotonic integer timestamps injected by caller.
  • 03. Continuously replenished token buckets eliminate cliffs.
  • 04. Explicit failure policies define degrade behavior on error.
